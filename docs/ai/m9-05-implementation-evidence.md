# M9-05 implementation and verification record

Status on 2026-09-23: implementation is under verification. The local model accuracy gate is **not** passed; see [evaluation](m9-05-evaluation.md). These results do not establish automatic legal compliance or guarantee the absence of defects.

## Contract and flow

The versioned wire contract is [`supplier-document-extraction.schema.ts`](../../packages/contracts/src/supplier-evidence/schemas/supplier-document-extraction.schema.ts), with parsed types exported from `@repo/contracts/supplier-evidence`. The Nest routes under `/api/v1/supplier-evidence-requests/:requestId/submissions/:submissionId` are `GET extraction`, `POST extraction-runs`, `POST fields/:fieldId/decision`, and `POST fields/manual`. The web gateway parses outgoing and incoming payloads. No public supplier route or browser Supabase connection was added.

`reviewer → Zod API → scoped application/repository → atomic Supabase RPC` governs every field decision. `worker → existing M8 local extraction/page map → local-only gateway → citation check → atomic completion` governs suggestions. A confirmed row is version-linked metadata only, not certificate validation, evidence acceptance, or a supplier-registry change.

## Deployment, rollback, and residual risk

Apply the additive Supabase migrations and regenerate the two database type copies before deploying API/worker and web. Existing M8 text/search and M9 review routes remain compatible. To roll back application behavior, disable tenant inference policy and the worker/new panel; retain provenance, field decisions, audit rows, immutable evidence, retention/legal-hold state, and M7 snapshots. Do not delete or reset existing data. The local synthetic PDF fixture is explicitly test-only and was not malware-scanned; it is not a substitute for the production clean-evidence pipeline.

Release still requires an installed approved local model, representative independently labeled accuracy/source-grounding results, a formally agreed confidence threshold, an Edge/previous-version browser matrix and complete WCAG 2.2 AA audit, realistic-load results beyond the bounded local probe, and resolution or explicit triage of the baseline full-suite failures. The existing tenant-export snapshot contract does not yet cover M8/M9 source evidence, so raw M9-05 run/field tables are deliberately excluded rather than exporting idempotency keys, leases, or non-portable citations; confirmed field metadata is therefore not in tenant archives yet and needs a coordinated M8/M9 export design. Until these gates are resolved, bulk confirmation remains disabled and manual review is the safe path.

The user chose on 2026-09-23 to leave the model gate blocked rather than install or select a local model, and to keep unrelated reporting/technical-file lint and M2 fixture repairs outside M9-05. No production database was accessed or modified during this continuation.
