# M7-05 versioned declarations of conformity

## Scope and preserved contracts

This feature creates product-scoped EU Declarations of Conformity (DoCs) under
the existing technical-file route. It preserves `/api/v1`, the session and
permission model, immutable M7 snapshots/exports, and the M3 SBOM contract.
It does not certify a product, select an assessment route, submit to a notified
body, or provide a cryptographic signature.

## Concrete problem and direct solution

An issued DoC must retain the exact documentation and product facts reviewed by
the responsible human; a live product record or snapshot-export job cannot do
that because neither owns draft/reissue state. The smallest durable solution is
a versioned Annex V template row plus a tenant-scoped declaration row bound to
one already-complete M7-04 snapshot.

## Selected patterns

- A feature-local port and Supabase adapter isolate the persistent database and
  storage boundary from controllers and React.
- Draft, issued, and superseded rows use an explicit lifecycle because reissue
  must preserve prior legal artifacts. Issuance only changes from a prepared
  immutable payload to issued after its generated bytes are durably recorded.
- Existing M7 snapshot locking, idempotency, private storage, and durable
  `audit_logs` transactions are reused. A generic workflow or evidence engine
  is rejected because M8 owns that later responsibility.

## Data and tenant boundaries

Every RPC accepts verified organization, actor, and product identity first and
checks a selected snapshot, source references, product/legal-entity facts, and
the issuing member in that tenant. Issuance requires a complete snapshot plus
unchanged current readiness and source digest. The actor is the named
responsible signatory and must retain `can_issue_technical_files`; capacity is
captured in the immutable payload. Reissues allocate a new product-local
version and atomically link the prior issued row as superseded.

The Annex V template is pinned to Regulation (EU) 2024/2847, Annex V, English
v1. V2 route data is human-selected only: `internal_control`,
`eu_type_examination`, or `full_quality_assurance`; notified-body and
certificate references are required only for the latter two. This is a product
record, not legal advice, and counsel must approve any production template or
language expansion.

## Failure modes and rollback

Missing, stale, archived, cross-tenant, incomplete, changed, or unauthorized
facts fail closed. Writes have idempotency keys and are never automatically
replayed by the browser. Private object upload can be retried against a
deterministic non-overwriting key when finalization fails; no issued row is
rewritten. The migration is additive: deploy DB before API/web; rolling back
API/web leaves immutable rows and objects intact.

## Verification

Tests cover Annex V and V2 schema rules, permissions, RLS/grants/search path,
snapshot/readiness drift, source rename, concurrent issue, reissue, immutable
hashes, private downloads, controller boundary parsing, and the browser
draft-to-issued-to-superseded journey. Issued content is retained with the
captured product retention projection; M8 may later consume metadata without
changing this contract.
