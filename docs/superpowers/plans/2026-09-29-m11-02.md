# M11-02 durable sync implementation plan

Baseline: clean `milestone-1` at `afe501a`. Approved 2026-09-29 after read-only
code and local Supabase inspection. BRD FR-INT-004/005/006 (V1), pages 35, 51,
55, 67–68. Preserve M11-01 and all auth, tenant, menu and M1–M10 contracts.

## Decisions

- Keep whole-batch domain commits and cursor advancement atomic.
- Replay preserves original mapping by default; rebasing/refetch requires explicit
  selection, current authorization, a fresh preview and manual commit review.
- Only reference conformance is implemented. Identity-only field mapping; no
  vendor adapters, executable transforms, job engine or event bus.
- Reuse connector current-map JSON, immutable run snapshots and plan-item record
  outcomes. Add only a focused `sync_run_attempts` table.
- Missing source values never become null writes. Validate discovered source
  schema and existing target Zod contracts; retain existing ownership policies.
- Use existing `connector_sync_record` retention authorities; no automatic purge.

## Execution sequence and ownership

1. Complete feature design before persistent workflow changes; write failing
   characterization/security tests before implementation.
2. Contracts/application worker owns strict shared schemas, pure mapping/retry
   policies, focused use cases and their infrastructure adapter. Agree RPC and
   gateway interfaces before parallel implementation.
3. Database worker owns CLI-created additive migration and rollback-only live SQL
   tests. Generation-fenced leases, expired-running recovery, attempts, atomic
   command/audit/replay and commit/cursor safety. Root reviews/applies locally and
   regenerates both database-type copies. Never reset or blanket-push migrations.
4. Worker worker owns adapter discovery/parsing, pinned mapping execution,
   missing/null policy, bounded records, safe classifications and worker RPC
   signature integration. Preserve recorded initiating/approving actors.
5. UI worker owns gateway/query/component tests and operational mapping/history/
   replay tables/forms, tenant drafts, accessible states and strict transport.
6. Root owns thin controller/module wiring, export/retention integration,
   security review, live-stack/E2E/load checks and completion evidence.

## Acceptance checks

- Mapping: missing/null/type/schema drift, protected fields, duplicate targets,
  sensitive source exclusion, mapping edit mid-run and invalid required creates.
- Transactions: poison records/rollback/counts, no cursor past unapplied work,
  cursor invalidation/full baseline CAS, crash before/after commit, expired lease,
  duplicate claim, stale worker, disconnect and tenant-fair scheduling.
- Retry: five automatic retries, exponential five-second base/equal jitter/
  300-second cap, Retry-After not-before, timeouts/outages versus auth/invalid
  failures, durable attempt history and restart recovery.
- Replay: preview/concurrency/idempotency/audit, linked child dry run, preserve/
  rebase/refetch, current permission/product scope and no active-run duplication.
- Security: secret canaries in responses/logs/audit/exports/caches, explicit org
  filters, composite FKs, pinned SQL search paths, explicit grants/non-forced RLS.
- Coverage: >=80% statements/branches/functions/lines for changed modules;
  focused suites, live SQL/races, `pnpm verify`, auth/navigation/M1–M10 regressions.
- Playwright MCP: seeded owner and isolated roles/tenants; keyboard/mobile/
  desktop screenshots; preserve unrelated data/mail/site state; report versions.
- Bounded history/detail/dead-letter load while workers operate: measure p95
  <400ms and p99 <1000ms; report dataset and local-environment limitations.

## Cutover and evidence

Pause connector workers, apply additive schema, deploy compatible API/worker and
require fresh review of legacy active plans without trustworthy snapshots.
Preserve completed historical records; unknown facts remain unknown. Roll back
only to compatible binaries while retaining schema, commands, snapshots and keys.
Deliver BRD-to-test traceability, schema/API links, screenshots, migration/backfill/
rollback notes, runbook and measured residual risks. Passing checks do not prove
zero bugs, exactly-once provider delivery or automatic regulatory compliance.
