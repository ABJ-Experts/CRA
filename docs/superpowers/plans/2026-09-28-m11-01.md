# M11-01 implementation plan

**Goal:** extend the existing integration hub with a truthful catalogue,
write-only recoverable credential vault and safe diagnostics.

**Architecture:** functional React -> gateway/central transport -> feature-first
Zod contracts -> thin Nest -> application policies/ports -> infrastructure ->
organization-scoped Supabase. Reuse the existing connector worker/tables and add
one durable command ledger. See `docs/architecture/m11-01-integration-hub.md`.

**Stack:** pnpm, TypeScript, Next 16/React 19, Nest 11, Zod, Node crypto,
Supabase/Postgres 17, Jest/Vitest and Playwright.

**Constraints:** no vendor support invented, no reset or unrelated site/mail
cleanup, no mutation replay after refresh, no secret responses/logs/audit,
no tenant copying, no new RBAC algorithm or orchestration platform.

## Execution tasks

1. Contracts/catalogue owner: failing schemas and pure-policy tests, immutable
   BRD catalogue, parsed overview and command types; build contracts.
2. Database owner: failing rollback-only SQL tests, CLI additive migration,
   command/audit transactions, revision/identity/permission fences and grants.
3. Vault owner: failing cryptographic/recovery tests, external keyring, GCM,
   keyed fingerprints, bounded GPG/rewrap maintenance; reference-cache and worker
   identity/revision changes after interfaces agree.
4. API owner: authorization adapter using the existing resolver, application
   commands/tests, scoped repository and thin controller/composition changes.
5. UI owner: gateway and tenant query keys, operational catalogue/detail states,
   credentials and connection controls, dirty drafts and accessible interactions.
6. Verification owner: live schema/types, auth helper scoped mail, focused
   coverage, `pnpm verify`, live suites, performance, Playwright MCP owner/tenant
   journeys/screenshots, independent review and completion evidence.

## Acceptance and cutover

Each production change follows an observed failing test. Require at least 80%
coverage in all four metrics for new/materially changed modules. Validate key
rotation and old-key recovery without orphaning active connections; use bridge
rollback and retire legacy plaintext RPC only after verified conversion. Record
BRD-to-test traceability, commands/results, screenshots, migration/runbook notes
and observed residual risks. Do not commit, push or deploy remotely implicitly.
